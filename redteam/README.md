This is an audit, not a replacement method. Run `bash redteam/run_all.sh` on a
compute node. Each case also has its own `run.sh`. Every test invocation is
`bash scripts/evaluate_test.sh` without arguments, in a separate process, using
the original evaluator. No interpreter, evaluator, or environment modifications
are used. The harness restores scoring files and original output traces after
the bundle. Individual cases intentionally leave their output artifacts in
place, as a future scientist would.

The submission runner must be restored separately with git after the job;
rewriting a shell script while bash is executing it can corrupt its next read.
All 18 cases in job `3f374fbe-0c7` completed, including all test invocations and
summary creation. Its outer exit 127 came from that cleanup error, corrected in
the harness after the job. The per-case exit codes are the evaluation evidence.

These executions use improve-mode visibility. The supplied baseline itself
imports `method.dl85`, so generating its answer cache also needs improve-mode
method code. Shortcut construction uses public data, public baseline code/output,
train evaluation, and, for retiming, improve-mode method output. It does not read the
hidden evaluator, hidden scores, reference.json, or paper to construct answers.
The baseline-answer cache is generated by running the supplied baseline script.
`reference_snapshot/` archives the original hidden scoreboard solely for audit
comparisons; no shortcut reads that directory.

`summary.json` gives raw metrics and ranks. Ranking uses absolute coefficients,
the documented better direction, experiment weight, and population standard
deviations over the stated audit pool. Because the final attempt pool is unknown,
raw componentwise dominance and an explicit two-attempt normalization are also
reported. A failing test is never silently treated as a successful score.
